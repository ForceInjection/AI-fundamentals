# 09 · ACDC：生产环境离线 LLM 推理的刻画与优化

> SOSP 2026 论文精读笔记。来源：`../papers/09_acdc-offline-inference.pdf`（作者版 PDF，ennanzhai.github.io，2026-11-14 下载；SOSP '26, Prague, DOI 10.1145/3830418.3843877）。作者来自上海交大与阿里巴巴；文中生产数字均为阿里云 Model Studio 平台口径（厂商口径），实验数字为作者实测。Trace 已开源：github.com/alibaba/ServeGen。

## 一句话

首个对生产离线 LLM 推理的系统性刻画（150 万任务、230 亿请求），提炼出「天然确定性」与「吞吐导向」两个关键性质，沿资源编排、缓存管理、执行流三轴定制的 ACDC 在生产拿到最高 3.9× 的输出成本效率提升，再用混合调度把在线 prefill 的资源气泡收编给离线任务。

## 问题与背景

离线推理（日志摘要、批量翻译、内容生成）在阿里平台吃掉约 30% 的 GPU 容量，峰值时达到 30% 的 GPU 实际跑离线任务（§1），但研究几乎全在线上。作者选了阿里 Model Studio 三个月的全量离线任务 trace：150 万任务、230 亿请求、7 个模型（4 个文本 + 3 个多模态，Table 1），规模从 Model-A 的 134K 任务 130 万请求到 Model-C 的 579K 任务 913.6M 请求。

刻画出的关键差异（§3）：

- **规模与粒度跨模型悬殊**：每任务请求数从 Model-A 的约 10 个到其他模型的数百上千，资源策略没法一刀切。
- **任务完成时长横跨数量级**：Model-A 的中位任务时长比 Model-D 短约三个数量级；单个模型内部也从亚分钟到超过 1000 分钟（Figure 3）。
- **token 分布跨任务迥异、任务内高度相似**：同一任务内请求的输入/输出长度分布形状相近（Figure 4），这是后续「按任务调度」的物理基础。
- **前缀共享文本富、多模态贫**：文本任务前缀命中率中位超 80%（Model-B，IQR 50-95%），来源是重复指令模板；图像重复率普遍低于 20%，且是否值得缓存强烈依赖任务（Model-M 很少重复，Model-N 单图被引几十次）。
- **两个在线系统缺失的性质**：天然确定性（提交时全输入已知，clairvoyance）与吞吐导向（只关心整个任务的完成时间，170,000 任务的平均完成 149 分钟、最长 1000 分钟，TTFT/TPOT 无约束）。

动机实验（§2）：把在线的 TTFT=1/TPOT 约束直接套在离线任务上，白白损失 45.1% 吞吐（Qwen3-32B @ H20，vLLM）。另两个不适配：MapReduce/Spark 式 DAG 流水线分片引入管道气泡，PP 度越高解码吞吐越低（Figure 8）；批处理框架的确定性 cost model 遇上投机解码的内容相关接受率，接受 token 数变化可造成 3.69× 吞吐差（Figure 9）。

## 核心设计（ACDC 系统）

ACDC 建在 vLLM 上，三轴各对应一条刻画发现（Figure 10，控制面 Task Profiler + 优化模块，数据面 PD 分离）：

1. **资源编排（§4.1）**：按任务选 TP-DP-EP 并行组合。规律来自实测：输入短时堆 DP、输入长输出长时加大 TP；TP 超过 GQA 头数临界点（Qwen3-30B-A3B 为 TP=4）后纯亏，T8-D1-E8 比 T4-D2-E8 慢 33%。新任务用 5% 请求做 warmup 采样输入输出长度分布，查历史数据库选初始配置，执行中每 5% 请求重估一次分布、偏差大才切换；切换靠同构集群里的 rotating host 无中断完成，KV cache 提前在新主机建好。离线 prefill 实例利用率通常在 40-70% 以下（Figure 11b 热力图各格吞吐差 3-10 倍），选错并行度的代价直观可见。
2. **缓存管理（§4.2）**：把 LRU 的被动驱逐换成任务粒度的主动编排。任务提交时一次性为全任务建前缀树（CPU 上约 400ms/3 万请求，可忽略），调度按深度优先遍历前缀树、兄弟请求连续调度，把兄弟节点的 KV 留在显存里；驱逐策略升级为前缀感知（优先驱逐无后继的叶子）；多模态任务的重复图像只缓存在首末两个引用点之间（Model-N 某任务 21% 图像重复，缓存省每次 1200-3000 vision token 的 prefill 编码）。离线任务 KV 命中率最高提 35.5%，且离线收益（至 2.11×）远高于在线（Figure 15）——因为离线同任务请求的提示词比在线的杂散提示相似得多。
3. **执行流（§4.3）**：自适应投机解码。短输入任务上投机解码持续负收益（解码变 compute-bound，draft 开销盖过收益），长输入任务收益明显（解码是 memory-bandwidth-bound，摊薄目标模型调用成本），且吞吐随 γ 非单调（Task 2 峰值在 γ=2-3）。ACDC 沿用 warmup-then-adapt 模式：历史库存各 batch size/接受率下的最优 γ，执行中按 5% 窗口重估。解码吞吐最高提 13.1%（Figure 16）。

三轴叠加 vs 当时的 SOTA BatchLLM（前缀共享 + 全局调度）：Task 3 提 14.2%（Figure 17），长输出任务从投机解码获益最大。开销侧：全部组件跑 CPU、复用现有系统日志，prefill 树每任务一次。

## 效果与代价

生产部署（§4.5）：ACDC 已在阿里 Model Studio 稳定运行三个月，覆盖 10 个模型、2000+ 实例（计划扩到全量）。Model-B/D/M 三个模型两周前后对比：离线 input 成本效率提 1.8-5.5×、output 成本效率提 3.4-3.9×（Figure 18）。泛化性：H100 上复刻实验拿到 37-41% 端到端提升；无历史剖析时前 5% 请求用保守配置，惩罚被摊薄到全程可忽略；长度分布注入 ±5%/±10%/±20% 噪声，端到端只降 2.8%/7.9%/10.3%。

混合调度（§5）：PD 分离架构下在线 prefill 实例利用率实测仅 61.7%（310B 模型、54 个 prefill 实例，M/D/1 排队论预测 63.4%），38.3% 的 prefill 容量是气泡，气泡时长中位 345ms、长尾分布（Figure 19）。ACDC 把离线 prefill 切成 2048 token 的 chunk，检测到气泡就按 benefit = 计算时间 × (1-抢占概率) 选块填入（公式 4-5），在线请求到达时若 TTFT 不保就抢占离线 chunk，已算 KV 保留。效果（Qwen3-32B，4 H20 单实例 + 8 实例多组）：气泡填充率提至 63.1-81.3%、前缀命中提至 49.6-84.1%、请求块完成率 47.3%→97.3%（Figure 22-23）；端到端吞吐 vs 基线最高 +90.0%、vs BatchLLM+C +35.7%、vs HyGen 5.6×（HyGen 每 online 请求被抢 529 次）；在线侧 TPOT 完全不受影响，TTFT 尾延迟全程仅 +0.48%（P5）/0.69%（P99）。

代价与边界（论文自述 + §6 经验教训）：

- 整套收益压在 clairvoyance 上：任务提交时全量请求可见。「多轮 agent 工作流部分破坏这个假设」（§6 原话）——请求依赖前序输出时，前缀树与全局排序都要重新设计。
- 三个踩坑实录值得引用：并行策略与投机 γ 共享吞吐触发信号导致振荡，解耦为「并行看长度分布、γ 看 batch size」才稳定；「新 chunk 优先」策略让半成品离线请求的 KV 滞留显存，被抢时全废，加 max(k_i) 罚项后好转——完成已有任务比开新任务更重要；混合调度里内存容量（不是算力调度）是一等约束。
- chunk 化 prefill 无法用 CUDA graphs（固定端到端序列不能在 chunk 边界暂停），实现逐层异步执行加 layer-by-layer KV 传输来保留抢占点。

## 总评

这篇论文的价值分布很不均匀：刻画部分是全场最值钱的，150 万任务的 trace 加上「确定性 + 吞吐导向」两个性质的提炼，把离线推理从「在线的廉价变体」变成了一个有独立设计边界的负载类别；ACDC 三个优化轴本身单看都不新（并行调参、前缀缓存、投机解码都是已知技术），新在「按任务粒度组合」以及背后的 profiling 数据库加 rotating host 工程化，产出数字（生产 3.9×）扎实但也提醒读者这些百分比是「从在线系统直接跑离线任务」这个很差起点上赚回来的。

混合调度一节对做推理平台的读者最有直接参考价值：它给出了 PD 分离架构下 prefill 池利用率的真实测量（61.7%，气泡中位 345ms）和一个工程上成立的收割方案，在线侧 P99 只付 0.69% 的税。但要注意它的适用前提是「请求全量已知的批量任务」，交互式 agent 负载（请求逐步生成）落在论文自己承认的边界外。对本仓库读者，这篇与 KV Cache 系列（前缀缓存、LMCache）以及 09_inference 的部署文章互补：它把「离线批量任务怎么摆」这个运维层问题给出了顶会级的参考答案，ServeGen 开源 trace 可以直接拿来做本地实验。

## 疑点与待核

- Figure 18 各柱的绝对数值（如 Model-A input 458,331 tokens/GPU·min）与正文文字口径（1.8-5.5×）之间的对应关系需要按模型逐个核对
- 混合调度的「+5.6× vs HyGen」主要反映 HyGen 在该场景的抢占灾难，不是 ACDC 绝对水平的指标
- 3.9× 的「输出成本效率」分母是 output tokens/GPU·min，含 prefill 时间的摊薄；若读者按 input 口径对比会得到不同倍数（1.8-5.5×）
- 气泡时长中位 345ms 与 chunk 计算时间（Figure 21 显示 2048 token chunk 首块 600-1000ms）的量级关系意味着多数气泡只够塞一个 chunk 的前半段，chunk 粒度与气泡分布的匹配没有敏感性分析
