# 02 · Amazon Bedrock：全球规模的基础模型服务

> SOSP 2026 论文精读笔记。来源：`../papers/02_bedrock-fm-serving.pdf`（Amazon Science 公开版，2026-11-14 下载；SOSP '26, Prague, DOI 10.1145/3830418.3843855）。系统名 WLM（Workload Management System），部署于 Amazon Bedrock。文中生产数字均为 AWS 厂商口径，实验为受控负载测试。

## 一句话

Bedrock 的跨区域工作负载管理层 WLM：把「请求进入」与「执行」解耦成逻辑执行池，用有界不一致的本地决策加异步对账取代请求路径上的同步全局协调，支撑每分钟数百万次、跨 30+ 区域的推理服务。

## 问题与背景

基础模型推理平台面临的独特组合（§1）：加速器容量稀缺且在区域间分布不均；请求资源消耗差数量级且输出 token 成本只在流式生成中逐步暴露；多客户共享容量但有不同延迟目标。Bedrock 每分钟处理数百万推理请求、横跨 30+ AWS region，容量集中在少数区域；四个服务档位（Provisioned Throughput 专用预留、On-Demand 共享池交互、Flex 低优先级非实时、Batch 异步容忍延迟）对应不同的容量权利与延迟容忍。

推理服务对准入控制有三个传统 RPC 没有的要求（§3）：每个推理请求都必须过准入（不像 RPC 只管不信任流量）；请求路径 p99 延迟必须压在 10ms 内；请求会消耗多少资源在准入时是未知的——输出长度要等生成完才知道。同步全局协调不可行：一次跨区往返 60-170ms（§3.1 与 §7 实测），比整个预算高一个数量级；而流式请求等完成再记账会让不准确状态持续数分钟。

由此得出两条架构原则（§1）：其一，请求进入与执行解耦，prompt-cache 稳定性作为一等路由约束（跨区移动请求可能作废可复用的 prompt cache，重算成本与前缀长度成正比）；其二，用有界不一致取代同步全局协调——本地缓存状态决策加后台异步对账，短暂超卖或次优路由通过对账电路与断路器兜底。

## 核心设计

请求流五段（Figure 1）：API gateway → 准入控制 → 流量分类 → CRIS 路由（源区域）→ 目标区域调度器 → 宿主层。四个子系统串成一条流水线，靠传播的元数据衔接，token 记账贯穿全程。

**分布式准入与配额（§3）**：每个配额（RPM + TPM 双桶，键为客户+模型+配额范围+服务档）用一致哈希分给一小组稳定的准入实例（每区域 N=3），由该子集独占记账与对账——不是让所有实例写共享存储（写吞吐会成为热点）。快路径完全本地：连续补充的令牌桶（避免固定窗口的边界翻倍效应），按启发式估算 token 扣减，流式执行期间周期性上报累计消耗，完成时最终对账修正。后台对账每 2-5 秒（随机抖动）经 DynamoDB 同步，复制延迟约 1 秒是实践下界。有界发散的界限明确：对账周期 × 负责子集大小；配额存储不可用时 fail-open 继续本地决策，恢复后收敛，长期权利不变。

**流量分类（§4）**：给每个请求打 STANDARD/ANOMALOUS 标签。检测两类需求变化模式（少量请求产生海量 token、大量短请求打满队列），token 速率与请求速率两个 EMA 分类器（相对客户自身历史基线 2.0×/1.5×，平滑常数 α=0.01）逻辑 OR。ANOMALOUS 只在目标区域争用时被降优先级，不拒绝；误标延迟处理优于拒处理，所以分类器故意偏敏感。基线在各 ingress 区域独立维护、不跨区复制——从新区域进入的流量冷启动期保守按 ANOMALOUS 处理。fail-open 时保持 STANDARD 并禁用降级：准入与分类的故障模式刻意分离，避免单点故障同时打掉两道闸。

**跨区溢出路由 CRIS（§5）**：目标区域按固定优先级排：可用性 > prompt-cache 局部性 > 延迟/利用率——固定序而非混合打分，让冲突可判定（宁可放弃 cache 也不放弃请求）。区域 headroom 公式 H_r = max(0, C_r·U_target − L_r)，加地理惩罚压制远区域。权重每 5 分钟离线重算、发布到各区域的 host-local cache，路由器查本地副本，信号收集完全在请求路径之外。prompt-cache 局部性靠 sticky-routing key（prompt 前缀哈希）加权一致哈希实现，权重调整时渐进移动并施加归一化约束，防止反复重映射导致 cache churn。首次派发只发本地，被拒后才试跨区（多付一次 RTT），每个服务档有队列时延容忍上限。

**请求调度（§6）**：区域队列分 shard，由持租约的 leader 调度（租约 1 秒、200ms 续一次，五次未续即接管，秒级恢复；新 leader 从 orchestrator 轮询重建队列）。客户公平性用 SFQ 散列到固定轮转队列；服务档与分类标签共同决定优先级（Provisioned pr10 → On-Demand pr50 → ANOMALOUS pr70 → Flex pr90 → Batch pr150，用 deficit round-robin 延迟低优先级而非饿死）；自适应并发用 AIMD（每接受 +2.7%，按严重度缩放的 0.85-0.95 乘性回退）；持续过载时先停收新请求（避免超时重试放大），ANOMALOUS 先于 STANDARD 被剥离。

## 效果与代价

评估（§7）混合受控负载测试与生产观测，全部厂商口径：

- **准入延迟**：有界不一致设计每请求中位 ~2ms，三区域 p99 都在 34ms 内；同步全局基线在两/三区域拓扑下分别是 2/60/211ms 量级。15 倍 offered load 范围内区域内延迟变化小于 1ms。持续过载下两设计都收敛到配置限额，报告级别偏离 ≤1.1%。
- **短期发散与 decider 数成正比**：一秒桶突发下，N=6 三桶实测准入 5.92/上限 6，N=9 九桶 8.65/9（Table 2）——发散上界 N 的理论预测被验证。
- **实例失效**：注入故障后 ~120 秒内补齐替换实例，期间无 client 可见失败。
- **路由与 cache 局部性**：生产权重自动调权 10 天 9 次无人工干预；粘性路由下 5 小时 99.94%、全天 99.78% 的前缀复用成功；跨 1000 前缀 token 的首 token 延迟组件因保住局部性降 45%（33.9→18.5ms）；全天 warm profile 首 token 中位降 10.7%（1,583→1,413ms）、p99 降 61%（8,687→3,397ms）。
- **优先级有效性**：work-conserving 调度启用后 Batch 消耗掉原本空闲的 70-100% 容量，周级 Batch 吞吐约 7×；容量受限期 STANDARD 可用性显著高于 ANOMALOUS（Figure 3-4）。
- **故障行为**（§7.5，部分为生产事故实录）：配额存储被限流时准入全部从本地缓存决策、无一失败；分类存储失效时保持 STANDARD；区域调度器失效时断路器秒级把流量切到其他区域，代价是跨区延迟与可能的 cache 局部性损失。

代价与边界（§8，论文自陈）：没有同步全局协调，对账窗口内允许暂时超额，协调好的多区域突发可利用这个窗口；token 计数在生成完成前都是近似，agentic 工作流尤其难估（工具迭代让输出长度可变，并发请求同时扰动配额与分类两个信号）；分类基线是区域局部的，跨入口不共享导致冷启动与口径漂移；为保 cache 局部性压慢了路由适应，阻尼权重让部分修正推迟到请求级重试才生效。

## 总评

这是一篇写作上非常自觉的系统论文：两个架构原则（解耦进入与执行、有界不一致优先）在开头立起，之后每个子系统都能回溯到原则，§2 的「组合与权衡」一节甚至预先交代了每个机制在什么情况下让步。对做推理平台的人，最有可迁移价值的是三件：其一，把「准入时消耗未知」当作一等约束来设计记账协议（估计-扣减-流式上报-终了对账的四段式），这个形态对任何按 token 计费的多租户服务都适用；其二，发散上界与负责子集大小挂钩的准入分片，用 N=3 的子集换全局一致性，实测发散恰好贴着 N 的上界走；其三，ANOMALOUS 只降级不拒绝、两个控制面的故障模式刻意分离——fail-open 的设计在这篇论文里不是口号，每个子系统都写明了挂掉时保什么丢什么。

需要打的折扣：这是厂商写自己生产系统的论文，对比基线（同步全局准入）是刻意构造的最弱对照，60-170ms 的跨区 RTT 让「同步协调不可行」论点成立，但中间态设计（部分同步、区域对区域协调）未被探讨；评估里最亮眼的数字（首 token p99 降 61%）来自单个模型、单账户、单工作负载的剖析，覆盖面有限；散装在 §7 各小节的实验没有统一的负载描述，重复实验的置信区间缺失。另外全文不涉及任何模型执行层技术（调度器之下直接是 hosting layer），它与 vLLM/SGLang 类系统论文处在不同层：WLM 管「请求从进入到落位」，执行层效率是另一篇论文的事。

对本仓库读者，这篇与 agent_infra 的 Substrate 一篇构成有趣对照：两者都在回答「海量高状态工作负载怎么摆」，Substrate 用专用控制面绕开 K8s apiserver，WLM 用有界不一致绕开全局协调，共同点是都拒绝在请求路径上做同步全局决策。与 09 号 ACDC 对读也有收获：ACDC 的混合调度明确依赖 clairvoyance（全量输入已知的离线任务），而 WLM §8 恰好点名 agentic 工作流破坏了 token 可预估性——两个系统在「可预估性」这个假设上互为镜像。

## 疑点与待核

- EMA 平滑常数 α=0.01 与「检测窗口近似宿主层扩容耗时」的对应关系只有定性说明，检测延迟的量化数据缺失
- Table 1 的参数表与正文数字自洽（2-5s 对账、5min 权重），但「生产中有效同步间隔 2s」是负载相关结论，其他负载形态下的表现未给
- §7.2 的 99.94%/99.78% 复用成功率测量「warm-set 大、cache 生命周期不同，不做因果比较」，与 45% 延迟收益的归因强度需要注意
- AIMD 参数 α=0.026、β∈[0.85,0.95] 标注「未调优」，Figure 5 只证明反馈环有响应，不证明操作点最优——论文自己承认
