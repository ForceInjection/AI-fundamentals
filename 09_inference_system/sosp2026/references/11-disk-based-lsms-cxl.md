# 11 · Disk-Based LSMs：部分一致 CXL 内存上的意外好索引

> SOSP 2026 论文精读笔记。来源：`../papers/11_disk-based-lsms-cxl.pdf`（作者版 PDF，2026-11-14 下载）。文中数字均为论文口径。

## 一句话

LSM 只在小 memtable 原地写，恰好塞进 CXL 内存仅有的硬件一致区，胜过移植的内存索引。

## 问题与背景

CXL 3.0 允许多台主机并发映射同一块 CXL 内存，但设备内存达 TB 量级，硬件只对几百 MB 保持缓存一致。论文把模型拆成小硬件一致区 scr 与大块非一致区 lnr，一致性开销在共享内存超过几百 MB 后不可接受（§2.1，p.3）。主机缓存可能留着 lnr 的陈旧数据，Tigon、Megalon 等系统把对象级一致性元数据放进 scr，访问 lnr 前先查、必要时刷缓存（§1，p.1）。

把现成内存索引改造上软件一致性是直接路线：作者移植 ART-OLC 与 OLC 版 B 树，得到 SC-ART、SC-BTree（§3.1，p.3），两条路都撞墙。ART 在 YCSB 数据下多数节点是最小的 Node4，1 亿键时 scr 装不下全部版本号，覆盖率跌破 50%，落在 lnr 的版本号每次访问都要刷缓存（§3.2，p.4）。调大 B 树 fan-out 能装下版本号，但一个键更新就作废整个节点的缓存（false invalidation）：write-heavy 负载下 fan-out 128 的 SC-BTree 只有 1.8 Mops/s，SC-ART 反而有 12 Mops/s（§3.3，p.4–5，图 2）。作者把病根归纳为可更新表面积（updateable surface area）：ART 与 B 树从根到叶都可能是原地修改点，版本号就得铺满全树；节点小则版本号放不下，节点大则误作废，两难无解（§3.4，p.5）。

反直觉点是答案出自为磁盘设计的 LSM：它只允许 memtable 原地写，SSTable 不可变，前者小到能进 scr，后者无需一致性追踪（§4.1，p.5）。

## 核心设计

**三层结构**（§5.1，p.6–7，图 5）。128 MB scr 切成三份：2 MB manifest 记录活跃 SSTable 的层级、键范围、ID；64 MB memtable 是 ART 结构，直接用硬件一致性；余下 62 MB 存 BUL 的逐节点版本号。lnr 侧是 BUL（bounded updateable layer，有界可更新层）加 L0–Ln 的不可变 SSTable。

**LSM 本身已占优**（§4.1，p.5–6，图 3）。朴素 SC-LSM 里，memtable 小、进 scr 靠硬件；SSTable 只在 compaction 中成批删除，每个 SSTable 有严格递增 ID 存在 scr，主机见到新 ID 就刷该文件区域的缓存，一致性粒度从节点降到文件。1 亿键、128 MB scr 下 SC-LSM 已显著超过 SC-ART，write-heavy 下比 SC-BTree 高至多 2.2×。短板在高写速率：写占比 50% 时每次读要探 49 个 SSTable，5% 时是 15 个（§4.2，p.6，图 4）。

**BUL 封顶可更新面积**（§5.2，p.7）。Prism 把 LSM 上层改回原地更新，但以「全部版本号塞得进 scr」为界圈定 BUL 规模。BUL 是 lnr 里的 ART，每个节点在 scr 占一个 64 位字：obsolete 标志、锁位、clock-sweep 访问位、42 位版本计数、16 位节点 ID、2 位节点类型。读子节点前查 scr 版本号，三选一：没见过则刷缓存重读；版本没变直接用缓存；变了则从 BUL 根重走。写者置锁位、改节点、刷缓存行、再抬版本号，读者靠版本变化发现并发写，数据记录的一致性挂在叶节点版本上（§5.5，p.8）。

**memtable 反转为热点缓存**（§5.3，p.7）。朴素流程是全部写先过 memtable，满则整块灌进 BUL，费 scr 且逐键 ART 插入昂贵。Prism 倒过来：写先查 memtable，命中就地更新，未命中直写 BUL；只有 BUL 的键再次被写才提升进 memtable。memtable 满时按 clock sweep 小批量退回最久未用条目（论文称 one-hit wonder filtering），刷写从整块变成增量摊销。

**SSTable 与 manifest**（§5.4，p.8）。每个 SSTable 建表时自带键到偏移的 ART 索引；Bloom filter 被明确去掉，理由是探一次 ART 的代价与查一次 Bloom 相当，省下额外内存。新 SSTable 先刷缓存行、再在 manifest 登记新 ID。键在层间迁移保证新机制下可见先于旧机制下移除：BUL 提升、memtable 退回、BUL 刷盘三个方向都持锁先插后删（§5.5，p.8–9）。作者用 Python 写了显式模拟 CPU 缓存的模型检查器，1600 万次操作、多组主机数与容量配置下未发现违反；注入「写者跳过 flush」「复用 SSTable ID」等缺陷能立刻抓到脏读（§5.5，p.9）。

读路径按 memtable、BUL、SSTable 顺序探查；L0 文件键范围可重叠须逐一探测，L1 起每层至多一个候选（§5.6，p.9）。删除用 tombstone，压到最底层才物理清除。后台任务（memtable 逐出、clock sweep 刷冷、compaction）全在单台指定主机上，层级文件数目标 L0 为 4、L5 为 10000（§6，p.9–10）。

## 效果与代价

评估是模拟环境：多主机 CXL 3.0 尚无商用设备，作者用 4 路 Xeon Gold 6418H，一个 NUMA 节点的 64 GB DRAM 当 CXL 设备、其余三个节点当主机，把节点 0 的 uncore 频率从 2.4 GHz 压到 0.8 GHz 模拟 CXL 访问延迟；scr 128 MB，预载 1 亿对键值（24 B 键、100 B 值），Zipf α=0.99，基线经过大量调优（§7.1，p.10–11）。

主要数字：峰值吞吐至多 9.4× 于移植的内存索引、15.1× 于现有 CXL 系统（摘要，p.1）；write-heavy YCSB-A/F 比 SC-BTree 高 7.4×/9.4×（§7.5，p.12）；范围查询在写占比 10% 后反超 SC-BTree，50% 写时高 6.0×，5% 写时仍落后（§7.4，p.11）；BUL 把 50% 写下的 SSTable 探测数从 49 大幅压低，热点缓存进一步降低（§7.7，p.12）。Twitter 54 个生产缓存集群 trace 上对 SC-BTree 全部获胜，平均 3.9×、最高 18×；对 SC-ART 在 43/54 个集群获胜，输掉的 11 个写占比均值 84% 且偏斜低，另有 5 个不足 4000 万键、SC-ART 仅以 7% 领先（§7.9，p.13）。scr 缩到 32 MB 时 Prism 在 YCSB-A/B 掉 31%/37%，SC-ART 最多掉 2.4×；与无限 scr 的理想 SC-ART 相比，Prism 写密集持平、读密集达 83–88%（§7.8，§7.10，p.12–13）。对现有 CXL 系统：Tigon 风格索引仅 1.4 Mops/s（低 8.6–15.1×）；Megalon 靠主机本地副本读占优，但每键每主机约 32 字节元数据，写负载下被 Prism 超 5.5×（§7.12，p.13–14）。

作者自认边界：故障模型沿用 fail-stop，任一主机或设备故障即整机停机，无恢复、无持久化（§5.7，p.9）；compaction 等后台任务单主机执行，分布式 compaction 留作未来工作（§6，p.10）。

## 总评

论文回答的问题界定得很干净：在大部分字节不缓存一致的共享内存上，可更新表面积小的结构占优。论证链完整，从动机实验（版本号溢出与 false invalidation 两难）到 LSM 贴合性的论证，再到 BUL 与热点缓存治 LSM 自身的 compaction 病，最后有模型检查和逐项消融兜底。结论强度也克制：与理想化无限 scr 的 SC-ART 相比，Prism 承认读路径更长（83–88%），换来的是写路径的量级优势。

没回答的集中在工程侧。真机口径缺位：延迟数字来自 uncore 降频模拟，真实 CXL 设备上 scr 容量与刷缓存走 CXL 链路的代价都可能不同。写入侧扩展性存疑：flush、逐出、compaction 全压在一台指定主机上，高写速率下这台机器是否成瓶颈、L0 堆积期的读延迟长尾如何，论文没有单独测量。

「旧结构映射新介质」这类工作的可迁移点在于顺序：先精确指认新介质的约束（哪部分字节必须硬件一致、哪部分靠软件元数据即可），再把老结构的天然属性（不可变文件、顺序写、小写缓冲）逐条对准。做存储引擎的读者能直接拿走两样东西：把一致性元数据当稀缺资源做预算分配（scr 里 2/64/62 MB 的切分是显式设计决策），以及用访问频率反转写缓冲方向（memtable 只收热点键，冷写直落 BUL）。

## 疑点与待核

1. BUL 版本字的位域标注对不上：论文写「Bits 45–61 store a 16-bit node ID」，45–61 共 17 位，疑为笔误（§5.2，p.7）。
2. BUL 数据节点在 lnr 原地修改，读者不加锁直接读 lnr 内容，仅靠 scr 版本号前后变化决定重试；写者多次写之间读者读到半更新状态的窗口，论文只给协议级描述，缺字节级分析（§5.5，p.8）。
3. 16 位节点 ID 用于区分节点内存重用后的陈旧缓存，容量上限与回绕处理未讨论。
4. 指定主机自身故障时后台任务如何接管，模型检查覆盖协议但不覆盖运维，论文未提（§5.5，§5.7）。
