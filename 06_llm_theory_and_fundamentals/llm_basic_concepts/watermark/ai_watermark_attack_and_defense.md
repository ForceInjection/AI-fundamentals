# AI 水印：道高一尺，魔高一丈

## 序章：一颗被换掉的骰子

2026 年 8 月 11 日，Anthropic 宣布将给 Claude 生成的文本打上水印，以满足欧盟《人工智能法案》自 8 月 2 日起生效的透明度义务。就在同一天，一个名叫 [watermarks-remover](https://github.com/guillaumemeyer/watermarks-remover) 的开源仓库在 GitHub 上诞生——它干的事恰好相反：把 Claude、Gemini、OpenAI 等各家产品可能留下的"AI 印记"，从文本和文件里清除出去。

四天后，面对沸沸扬扬的用户反弹，Anthropic 发布[官方博客](https://www.anthropic.com/news/claude-text-watermark)拆解水印的技术细节，还打了一个生动的比方：玩大富翁，骰子被换成了《圆周率》。博客里明说，轻度的修改洗不掉水印，但逐词重写可以。而此时，仓库早在博客发布前三天，就把"重写"做成了流水线；到第六天，它已经斩获一万一千多颗星。

官方刚亮出骰子的秘密，玩家已经备好了另一颗骰子。一场攻防战就此开打。这篇文章记录的，是这场战争的前四个回合，以及它们指向的那个没有终局的未来。

## 一、棋局是怎么摆下的

这场战争的棋盘，是监管铺开的。2024 年 8 月，欧盟《人工智能法案》生效，其中第 50 条给 AI 生成内容定下透明度义务——技术上必须"可被识别"，相关条款自 2026 年 8 月起全面适用；中国随后发布《人工智能生成合成内容标识办法》，自 2025 年 9 月起，AI 生成内容须同时携带显式与隐式标识。全球主要经济体的监管者达成了一致：AI 的产出，必须能被认出来。

厂商并非被动接招。深度伪造的成本已经趋近于零——一段以假乱真的换脸视频，几分钟就能出炉；AI 垃圾内容的生产速度，也早已甩开人工审核的吞吐能力。监管要"检测"，平台要"溯源"，厂商要"合规"，三方合力之下，一个行业联盟站了出来：Adobe 牵头、Google、OpenAI、Microsoft 先后加入的 C2PA，试图把水印升级成签名——在文件里嵌入一份带签名的清单，写明内容由谁、用什么工具生成。这就是"内容凭证"。

至此，标记技术分裂成两个流派：隐式水印与显式签名。前者不改变用户的感知，信息藏在字符、概率或像素里，只供事后检测；后者以明文元数据宣告身份，可查、可验——当然，也可被剥离。而所有后续故事的关键，藏在一句反直觉的话里：最厉害的文本水印，根本不藏任何东西。它留下的不是字符，而是一条采样痕迹——理解这一点，就拿到了看懂整场战争的钥匙。

## 二、第一回合：隐形字符，死于一条正则

**出招**。第一代水印手法简单粗暴：把信息藏进"看不见的字符"。Unicode 里有一整个地下世界——零宽空格(U+200B)与零宽连接符家族，能反转阅读顺序的双向控制符(RLO/LRO)，连渲染器都不显示的标签字符(U+E0001–U+E007F)，变体选择符、私有区字符，以及用西里尔字母"а"冒充拉丁字母"a"的同形字。它们在屏幕上不留痕迹，却能拼出一条机器可读的隐藏消息。曾有工具用它们给文本"盖章"，肉眼看去，文本和原来一模一样。

**拆招**。在进入战场之前，先看一眼这个项目的骨架：一个纯 Markdown 编写的 Agent Skill，加一个仅用 Python 标准库、零第三方依赖的 HTTP 服务。Skill 里没有一行清洗代码，它只是薄客户端，用 curl 和 base64 JSON 驱动服务端，宿主机连 Python 都不用装。整个项目把"判断"与"执行"分开——先检测，后清洗，清洗引擎还会如实报告自己有哪些武器，只承诺做得到的事。

watermarks-remover 的第一层回应只有一个字：删。它的 Layer A 把上述码点列入清除清单，激进的同形字模式甚至能把字母替身打回原形。

但这一层真正见功力的地方，是它知道"哪些不能删"。有些隐形字符是文本的承重结构：emoji 序列靠零宽连接符和变体选择符粘合，波斯文和天城文靠连接符拼写，国旗干脆就是一组标签字符，蒙古文、高棉文、谚文里也各有自己的变体选择符和填料。Layer A 的规则由此定下：同样的字符夹在纯 ASCII 之间，是藏污纳垢的载体，剥除；出现在合法脚本的语境里，是文字的骨头，保留。正因如此，它才敢说自己"无损"——既删得干净，又不会把一篇波斯文拆散架。

**胜负手**。进攻方琢磨了多年的障眼法，防守方一套确定性规则就清场。这一回合毫无悬念：藏在字符里的信号，删掉字符就没了。水印的制造者们也深知这一点，所以他们早就不赌这一层了。

## 三、第二回合：换骰子

**出招**。字符藏不住，那就干脆什么都不藏——把水印写进"概率"本身。大语言模型生成文本，本质是逐 token 掷骰子：每一步从词表的概率分布里采一个词。统计水印的思路是：换掉骰子。2023 年，Kirchenbauer 等人提出 [KGW 方案](https://arxiv.org/abs/2301.10226)，把词表按"密钥 + 前文"的哈希分成绿名单与红名单，生成时悄悄偏向绿名单；检测者拿着同一个密钥数一数命中数、算一个 z 分数，一段足够长的水印文本就现了原形。2024 年，DeepMind 的 [SynthID-Text](https://www.nature.com/articles/s41586-024-08025-4)（发表于 Nature）更进一步，以密钥驱动的锦标赛采样取代粗暴的名单偏向，宣称不伤生成质量。Anthropic 官方博客后来确认，Claude 的文本水印正是 SynthID-Text 的一个版本；而按 Anthropic 帮助中心的说明，2026 年 8 月 2 日之后发布的新模型，将在全球范围打上内容标记——包括这类文本水印，以及文件级的 C2PA 签名。

博客里那个著名的比方，正是这一回合的缩影：大家玩大富翁，官方偷偷把骰子换成了《圆周率》——玩家每次按圆周率小数点后的数字走。玩家看来，每一步依然"随机"，文本质量没有任何下降；但官方事后拿着那本《圆周率》核对步数轨迹，一眼就能认出：这是用我的骰子走出来的。

这套魔法有两个死穴，也是整个攻防逻辑的支点：检测必须持有密钥；文本必须足够长，才攒得出统计样本——短文本、低熵文本（代码、公式、清单）里，指纹会淹死在噪声中。而最致命的一点是：水印在"选词模式"里，不在字符里。删字符无效；想毁掉它，只有一条路——重写选词本身。

**拆招**。开源社区的回应，是把重写这件事工业化。watermarks-remover 的 Layer B 把重写的粒度定在句级：扰动的是每一句的语序、连接词与句子边界，整段整段地换语义反而无效。它引入一个非源头模型执行重写：想洗掉 Claude 的文本，就别用 Claude——换一个本地开源模型，用它的概率分布把全文重新"走"一遍。原密钥的哈希轨迹长在原模型的采样偏向上；换一颗骰子重走棋盘，轨迹自然作废。

重写的配方分成四级，火力逐级加强：默认的 paraphrase 换语序、换连接词、打散句子边界、在意义允许处替换实词虚词，同时保住事实、数字与名称；humanize 追求"像人类从零写就"；回译把文本翻译到另一门语言再翻回来，洗牌最狠；结构化重建则先把全文提炼成要点大纲，再重新成文——最干净，也漂移最大。每轮之后还要再跑一次 Layer A，清扫重写过程中可能带进来的新字符。

这一招至今有效，还有一个行业层面的原因：主流厂商的文本水印是逐 token 嵌入的——流式生成的约束摆在那里；更鲁棒的段落级方案仍躺在论文里。重写类攻击的窗口，暂时还开着。

**胜负手**。庄家换了骰子，玩家从抽屉里摸出另一颗。第二回合攻守易位：破解方不再需要密钥，只需要一个"非源头模型"，以及承受文本降级的觉悟。保意不保字，是这一回合的代价。

## 四、第三回合：文件的身份证，与拆弹钳

**出招**。文本之外，文件本身成了战场。C2PA 的签名清单藏进 JPEG 的 APP11 段、PNG 的 caBX 块、ISOBMFF 容器的 jumb/uuid box；EXIF、XMP 里躺着设备与软件信息；DOCX 的属性、HTML 的 generator 标签、Markdown frontmatter 里的 AI 声明键，全是"此内容由 AI 生成"的告白。

这里有一道伏笔：签名分硬绑定与软绑定。硬绑定，清单物理存在于文件之内，剥掉元数据就清场；软绑定，把水印打进内容本身——像素或波形——用它回链远程保存的清单。元数据删得再干净，内容指纹还在。后者是防御方专门为"拆弹专家"准备的。

**拆招**。watermarks-remover 的文件层，把拆弹做成流水线：PNG/JPEG/WebP 丢 APP11、caBX、jumb/uuid 块；AVIF/HEIC 走 ISOBMFF 路径；PDF 要 exiftool 与 qpdf 联手才能真拆，缺了只能降级；DOCX/ODT 重写 OOXML 压缩包；HTML 清 generator 与 JSON-LD；Markdown 删 AI 键；连 SVG、HTML、Markdown 里内嵌的栅格 data URI 也被递归清理——那是另一个容易漏掉的藏匿角落。

一个细节能看出它的防御式设计：文件类型走"扩展名 + magic bytes"双通道判定，文本工具直接拒绝二进制输入。这是旧版用教训换来的——早期实现曾把图片误当文本处理，一洗就坏。

**胜负手**。硬绑定的身份证，拆得干净、拆得可验证——清洗后再跑一次检测，元数据在不在，一目了然。但厂商已经埋好下一手：软绑定。战争由此升级，战场从文件头转入像素。

## 五、第四回合：像素里的信号，重建里的战争

**出招**。这一回合，连像素都不可信。Google 的 SynthID-media 把信号打进图像频域，视觉上不可见；StegaStamp 用端到端训练的神经网络做隐写，解码器就是它的照妖镜；Tree-Ring 更进一步，把同心圆图案写进扩散模型的初始噪声——生成那一刻，水印就被"印"进图像。删 EXIF、删 C2PA，全都无济于事；信号在像素里，要动它，只能动像素本身。

**拆招**。watermarks-remover 掏出了整场战争最重的武器：CtrlRegen。它用 ControlNet 引导一次受控的重新生成——不是在原图上涂抹，而是"按原图重画一遍"，水印所在的频域结构在重画中被打散；另一个可选后端 MarkDiffusion 提供 DiffusionPurification，一种对扩散水印的盲再生攻击：不认水印方案，代价是图像漂移更大。

**胜负手**。信号确实能被破坏，但这是四回合里唯一没有便宜胜利的一局：GPU、时间、像素细节的漂移，缺一不可；而音视频水印，至今仍是无人区。这一回合，双方打平。

## 六、左右互搏：怎么证明"删干净了"

去除工具最容易被诟病的一点，是自说自话：你说水印没了，拿什么证明？厂商不公开检测器，这就是一道没有标尺的题。watermarks-remover 的办法，是把清华主导的开源水印评测框架 [MarkLLM](https://github.com/THU-BPM/MarkLLM) 搬进来，在本地搭起一场"左右互搏"：先用 KGW 或 SynthID 的配置给一段文本打上水印，再用 Layer B 清洗，最后用 MarkLLM 的检测器打分——报"未发现水印"，这一轮才算通过。

这个闭环把"尽力而为"变成了"可度量"，但它的边界同样写在明处：同配置下的自测，不是厂商官方检测器。真正的判决，还握在厂商手里。而在厂商公布检测器之前，破解方只能和自己对练——练得再熟，也不算数。

## 七、终局与下一局

四回合打完，战局陷入僵持。破解方最深的困境不在工程，而在信息不对称：没有官方的检测器与密钥，一切"已清除"都只是 best-effort。厂商之所以不公开，是因为学术界早已证明——检测器一旦公开，攻击者就能针对它训练自适应攻击；公开，即失效。于是防守方必须把方法藏起来，而破解方只需要把方法开源。这组不对称，决定了防守方永远是更被动的一方。

代价也是真实存在的：文本重写保意不保字；像素重建要 GPU、要时间、要接受漂移；短文本上一切努力收益递减。项目自己也把边界划得清清楚楚：C2PA 软绑定清不掉，音视频水印不在范围，训练后门（trigger phrases 之类的模型级标记）更是无解。在一个万物皆可吹的领域，这种"承认不能"的诚实，反而构成可信度。

下一轮的钥匙，握在双方手里：厂商随时可能公布官方检测器，那将是全部攻防重新洗牌的起点；开源侧则在打磨更高保真的重写与更强的配方。而棋盘之外的问题，比棋盘上的更重要：谁有资格决定"你的内容带不带标"？工具是中立的，去标记的正当性取决于内容归属与用途——清理自己拥有的内容，是隐私与卫生；用它造假，是另一回事。责任在使用者，不在工具。

## 尾声

回到序章那颗骰子：官方换了骰子，玩家找到了另一颗骰子。四个回合，胜负手都归结为同一个问题——信号藏在哪里，破坏它的成本有多高。藏在字符里，一条正则删干净；藏在概率里，重写整篇文本；藏在元数据里，剥离文件块；藏在像素里，重建整张图像。成本逐层递增，而每一层的"清除"都只是相对的。

道高一尺，魔高一丈；道高一丈，魔高十丈。这句老话原本笃定"道"必胜，但在水印的战场上，攻守双方每个回合都在互换位置，谁也压不住谁。社区里还流传着一个段子：有人想让 Claude 自己跑一遍去水印插件，被礼貌而坚定地拒绝；转头把插件装到别家模型上，一次通过。段子真假不论，它道破了这场战争的底色——厂商比谁都清楚，那枚钢印意味着什么。

这场猫鼠游戏没有终局，因为它的真正战场不在代码里，而在"内容归属权"的定义上。下一颗骰子会是什么？答案写在双方的实验室里。
