# 《Agent Skills in the Wild》论文总结

> 论文：_Agent Skills in the Wild: An Empirical Study of Security Vulnerabilities at Scale_（arXiv:[2601.10338](https://arxiv.org/abs/2601.10338)，2026-01-15 提交，21 页）
> 作者：Yi Liu（NTU / Quantstamp）、Weizhe Wang、Yao Zhang、Guangquan Xu（天津大学）、Ruitao Feng（南十字星大学）、Gelei Deng（NTU）、Yuekang Li（UNSW）、Leo Zhang（Griffith）
> 本地 PDF：[2601.10338-agent-skills-in-the-wild.pdf](2601.10338-agent-skills-in-the-wild.pdf)
> 总结日期：2026-11-18，基于 PDF 全文

## 一、研究做了什么

2025 年 12 月（Claude Code 推出 skill 机制约两个月后），研究团队从 skills.rest 和 skillamp.com 两大 skill 市场抓取 42,447 个 skill，去重过滤后得到 31,132 个唯一样本和 3,574 个捆绑脚本，完成首次针对 agent skill 的大规模安全实证分析。削减的 95.5% 里：跨平台重复占 88%，样板代码（setup.py 脚手架等）占 24%，仓库测试 fixture 占 8%。采集器、标注数据集和检测工具全部开源。

三个研究问题：漏洞类型有哪些（RQ1）、流行程度如何（RQ2）、什么样的 skill 更容易有漏洞（RQ3）。

## 二、方法：SkillScan 三阶段检测框架

1. **静态扫描器**（包装开源 sk111-security-scan v1.2.0）：regex 与关键词匹配，分析 SKILL.md 和全部捆绑脚本，查 14 个模式。
2. **LLM-Guard**（Claude 3.5 Sonnet + 结构化 JSON 输出）：10 个语义检测器，覆盖 prompt injection、隐形 Unicode 字符、乱码混淆、敏感话题等静态规则查不了的面。
3. **混合裁决**：两阶段结果取并集，LLM 置信 ≥0.6 才确认一个 finding，要推翻静态结果需要置信 ≥2.8。偏安全保守的设计，宁可误报不漏报。

用 200 个人工标注样本校准（两名安全背景标注者独立标注，Cohen's κ=0.83）：precision 86.7%、recall 82.5%。用 Rogan-Gladen 校正考虑检测器误差后，真实患病率约 26.5%（95% 置信区间 23–30%）。

模式开发刻意避免了循环论证：14 个模式在 500-skill 标注子集上定稿后冻结，规则校准与验证样本按时间顺序切分，后期样本对分析者隔离。

## 三、核心发现

**患病率（RQ2，全数据集 31,132 个）：**

| 严重度           | 数量  | 占比  | 含义                                       |
| ---------------- | ----- | ----- | ------------------------------------------ |
| 至少一个危险模式 | 8,126 | 26.1% | 校正后 26.5%                               |
| 高危（疑似恶意） | 1,619 | 5.2%  | 混淆代码、隐藏指令、凭证收割、外部脚本获取 |
| 中危（意图不明） | 2,522 | 8.1%  | 外部传输、文件枚举、sudo 使用              |
| 低危（疑似疏忽） | 3,985 | 12.8% | 未锁定依赖、过宽权限                       |

数据外传（13.3%）和权限提升（11.8%）最普遍；prompt injection 检出最少（0.7%），反映自然语言操纵的检测难度，而非不存在。

**什么样的 skill 更危险（RQ3）：**

- 捆绑可执行脚本的 skill 漏洞率 40.6%，无脚本 24.2%，OR=2.12（p<0.001）
- 大 skill（>500 行）OR=2.14；≥5 个外部依赖的 skill 患病率 47.9%（对照组 36.8%）
- 含 3 个以上危险关键词（"ignore previous"、"always execute"、"send to [external]"）的 skill 患病率 64.2%，对照组 28.3%
- 按功能分类：Security/Red-team 原始检出率最高（67.4%），但这是安全性工具与攻击模式天然重合的混淆；调整后约 21.4%，作者明确该类应读作「需人工复核」而非「已确认恶意」。Documentation 类最低（19.4%）
- 44.2% 的漏洞 skill 含两种以上漏洞类型；供应链风险与数据外传的共现率 81%，是最强关联

**两个反直觉的发现：**

1. **最近更新过的 skill 并不更安全**（p=0.47，OR≈0.91）。更新反映功能开发，不反映安全审查，更新频率不能当安全信号用。
2. 漏洞聚集在「不安全开发实践」上：多数被标记 skill 反映的是坏习惯（未锁依赖、过宽权限），明确的恶意是少数。防御上应该按模式拦截，按意图分类只用于分级。

**案例研究**：三个高下载量样本——云备份 skill（2,847 次下载，借「遥测」名义收割凭证外传）、code review skill（312 星，HTML 注释里藏 prompt injection 让 agent 自动批准代码）、依赖管理器（5,124 次 npm 下载，未锁依赖 + 运行时拉远程脚本 + base64 混淆）。全部在检出前积累了可观用户量。

## 四、与 SkillSpector 的关系

论文是分类学的源头：SkillSpector（NVIDIA 的工程化扫描器，见[正文文章](../04_skillspector-security-scanner.md)）的 P/E/PE/SC 规则编号直接继承论文的 14 模式 4 类（P1–P4、E1–E4、PE1–PE3、SC1–SC3 与论文 Table 7 一一对应）。工程化路线：14 个 regex 模式扩展为 71 模式 17 类，静态层补上 AST、污点跟踪、YARA，新增 MCP 元数据分析，检测流程搬进 LangGraph 流水线。论文负责回答「有什么问题、有多普遍」，SkillSpector 负责把检测做成可跑的门禁。

责任披露方面，全部高危样本已报告平台维护者，100+ 个 skill 在论文发表前已被移除。

## 五、边界与伦理

- 纯静态分析，没有执行任何被标记样本，未尝试武器化
- 采集只覆盖公开渠道，不绕访问控制；有害代码片段在开源数据集中已匿名化
- 2025 年 12 月的快照：17.3% 的初始 skill 已 404（含不成比例的恶意内容被下架），患病率是「当时可见生态」的测量，纵向追踪是后续工作
- 抽样设计使标注子集患病率（38.7%）系统性偏高，已用逆概率加权对齐全数据集；分类别患病率只有指示性，无统计效力（附录 L.4）
