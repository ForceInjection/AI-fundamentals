# 技能分类体系设计（skill kind 体系）

> 状态：设计冻结（v4）。P1 已实施（catalog taxonomy + 断言 + items 回写 + analyze 三视角 + 双 matrix），P2–P4 待执行（见 §十）。
> 适用范围：`data/skill_catalog.json`、`scripts/extract_skills.py`、`scripts/import_ai_companies.py`、`scripts/refresh_catalog_stats.py`、`scripts/analyze.py`、四个可视化页面、两篇文章。

## 一、背景与问题

词表经多轮扩充后达到 109 个技能（数据中出现 101 个），但所有词被放在同一个平面 `items` 里混排排名，产生了三类系统性问题：

1. **跨性质比较的伪结论**：「多模态 38.2%」（领域词）压「CUDA 1.8%」（技术词）、「评测 2006 条」（工作活动）排「CUDA」前面——比较对象不同质；
2. **榜首被背景词占据**：领域词天然密度最高，「大模型/LLM 74.4%」永远排技能榜第一，榜单失去信息量；
3. **边界词反复争论**：模型量化 / 评测 / SRE / SLA/SLO 等词横跨多层，逐词拍板无法收敛，且随词表扩充会再次出现。

三轮评审与抽查验证确认：**提取本身正确（漏标为 0、边界用例全部通过），问题出在分类组织**。本设计不改提取、不改数据、不改词表成员，只对 109 个词补加性质维度并重组分析产物。

## 二、设计原则

1. **三个分析视角，而非三层语义**：一个词可以同时是市场主题、工作内容和可学习技术，主归属（kind）只决定它出现在哪个视角的榜里，不宣称语义唯一真值；
2. **主 kind + facets**：每词恰一个主 kind（决定主榜归属），可选 facets 记录其他视角（仅供交叉查询，不进其他层主榜，避免重复计数）；
3. **base 正交标记**：base 与 kind 无关，只标「行业默认词」（当前仅 大模型/LLM 一处，人工认定、不按密度自动划分）；与 roadmaps 的 `base`（学习底座）不同义；
4. **count 与 ranking 分离**：数据零改动 → 每词 count 不变；但按 kind 分榜后排名与文章结论必须重写；
5. **单一来源**：109 词的 kind/type/work_type/scope/scope_facets/facets/base 唯一来源是 catalog 的 `skill.taxonomy` 表（109 行机器可读数组），由校验断言保证一致性，禁止散文维护；
6. **scope 正交维度**：scope 与 kind/type 正交，回答「这个技术主要用在哪」（general / ai-infra / agent-infra）；只加在 technique 词上，跨域时记 `scope_facets`。

## 三、kind 判定卡（两段式，可复现）

第一段定主 kind（按 R1 > R2 > R3 优先级，命中即停）：

```text
R1 具名可学习对象——有具体产品/框架/库名或具名方法名？（类目/栈词不算，见 R2）
   （例：CUDA、vLLM、RLHF、MoE、模型量化、模型蒸馏、提示词工程）
   → technique
R2 市场主题/岗位方向——能对应 sub_category 或独立招聘方向的词？
   （例：大模型/LLM、Agent、模型训练、模型推理、预训练、多模态、机器学习、强化学习、知识图谱、芯片、数据中心）
   → topic
R3 通用岗位动作/角色/指标/能力（无专有技术名的工作行为词）？
   动作：评测 / 性能优化 / 微调 / 推理优化 / 模型部署 / 数据合成 / 数据标注 / 故障排查
   角色：SRE
   指标：SLA/SLO
   能力：可观测性
   → work
兜底：三问皆否 → 不入词表。
```

第二段：technique 词按 §四 学习单元定义表定 technique_type（多个 type 都像时取主要 type，另一侧记 facets），并按 §四·补 定 scope 应用域（多个 scope 都像时取主 scope，另一侧记 `scope_facets`）；work 词按工作性质标 work_type（action / role / metric / capability）。

已知的语境排除（提取层，见 `alias_context_guards`）：量化排除 轻量化/向量化/可量化 与 量化策略/量化投资；agentic 排除 Agentic RL；AIGC、MaaS 为业务方向词，不设别名。

## 四、technique_type 学习单元定义表（6 类）

| type                 | 学习单元（一句话定义）                                           | 成员数 |
| -------------------- | ---------------------------------------------------------------- | ------ |
| `language`           | 编程/建模语言，学习单元是语言本身                                | 9      |
| `framework`          | 可引入的框架/库与编程模型，学习单元是 API 与用法                 | 16     |
| `platform-tool`      | 可部署/接入/运维的工具、平台与协议，学习单元是部署运维与协议接入 | 30     |
| `hardware-interface` | 物理硬件与互联/存储接口，学习单元是选型与使用                    | 8      |
| `data-system`        | 数据存储与处理系统，学习单元是建模与调优                         | 14     |
| `method`             | 具名算法/架构/优化方法，学习单元是思想与调优                     | 8      |

判定顺序：language → framework → platform-tool → hardware-interface → data-system → method；多个都像时按「主要学习单元」取主 type，另一侧记 facets。

本轮迁移记录：CUDA → framework（编程模型）；BDSL / IBoF → data-system（存储系统）；Function Calling → platform-tool（LLM API 协议接入）；InfiniBand / RDMA / RoCE / NVMe 保留在 hardware-interface（互联/存储接口）。

### 四·补、scope 应用域（technique 词的第二维度）

`technique_type` 回答「这是什么学习对象」，`scope` 回答「它主要用在哪」——两者正交。每词一个主 scope，跨域时记 `scope_facets`。

| scope         | 定义（一句话）                                                                            | 成员数 |
| ------------- | ----------------------------------------------------------------------------------------- | ------ |
| `ai-infra`    | AI 基础设施：GPU/加速器、训练/推理框架与引擎、通信库、AI 集群调度、模型优化方法、向量检索 | 37     |
| `agent-infra` | Agent 基础设施：Agent 协议/接口、编排框架、检索增强、提示工程                             | 7      |
| `general`     | 通用底座：OS、容器、CI/CD、云、监控、协议、编译器、虚拟化——非 AI 专属但 AI 大量使用       | 41     |

通用底座中的 K8s / Docker / Linux / 云 / 监控 / 编译器 / 虚拟化 带 `scope_facets: ["ai-infra"]`——主域 general，AI 侧用 facet 表达。

规则：scope 只加在 technique 词上；`refresh` 校验 technique 必带 scope ∈ 三值、scope_facets ⊆ 三值且不含自身 scope；非 technique 词不得有 scope。

## 六、facets 规则与多面词表

**facets**（跨 kind 视角）：topic 词高频兼工作内容 → facets 记 work；类目/栈词归 topic 时 → facets 记 technique；具名方法型 work 词 → facets 记 technique。不进入其他层主榜（无重复计数），仅用于交叉查询与交叉展示。

**scope_facets**（跨应用域，只用于 technique）：通用底座词 AI 侧使用 → scope_facets 记 ai-infra。同样不进主榜，仅交叉查询。当前 12 个词带 scope_facets：Kubernetes / Docker / Linux / 云 / 监控 / 编译器 / 虚拟化 等通用底座词 + Slurm / GPU池化 / DCGM / nvidia-smi 等 AI Infra 平台工具词。

1. taxonomy 恰 109 行、名称唯一、与 items 键集完全一致；
2. 每行恰一个 kind；kind=technique 的行必带 type，且 scope ∈ {general, ai-infra, agent-infra}、scope_facets ⊆ 三值且不含自身 scope；kind=work 的行必带 work_type ∈ {action, role, metric, capability}；kind∈{topic,work} 的行无 type、无 scope/scope_facets；

4. facets ⊆ {topic, work, technique} 且不含该行自身 kind；
5. items 上的 kind/type/work_type/scope/scope_facets/facets/base 与 taxonomy 完全一致（refresh 回写后断言）。

## 八、分析产物设计

### skill-tree.md（三视角结构）

1. **主题覆盖率（提及率）**：topic 词按提及率列出，大模型/LLM（base）置顶单独说明「行业默认词」；不叫技能榜；
2. **technique 主榜**：按 6 个 type 分组，组内按 scope 分块（AI Infra / Agent Infra / 通用底座），块内按提及率排名，组间不比较，overall 只作索引；共现榜只算 technique；
3. **工作内容分布**：work 词按 `work_type`（action / role / metric / capability）分组，组内按提及率排名，组间不比较；不做学习优先级表述；
4. 各线高频技能：分「技术栈高频（technique）」与「工作内容高频（work，按 work_type）」两段；方向级子树保留全部词（作为索引）。

### 页面（P2，三视角切换）

- 谱系树：保留全部词，节点加 kind 徽标，支持按 kind 过滤；
- 明细表：加 kind 列；
- Sankey 与技能热力：technique 口径（含 type 维度），不再被领域词霸榜；
- 新增 topic/work 两个视角块（主题覆盖率、工作内容分布）。

## 十一、已否决的替代方案

- **按密度自动划 base**：74% 的 LLM 是默认词，但 57% 的 Agent框架是有信息量的市场信号——密度线划不出语义边界，改为纯人工认定；
- **AIGC / MaaS 作别名**：业务方向词混进技能榜（「AIGC 产品实习生」被标多模态），已删除；
- **截断取前 12**：系统性丢弃短名技能（Go/GPU/MoE 在多技能 JD 里总排最后），已改为全量保留；
- **给「量化」逐个加后置排除词**：改用前后置双向语境排除并定义在 catalog，新语境词只加配置不改代码。

## 十二、遗留决策（不在本设计内）

1. 残余无技能记录（73 条，均为 AI 相关但文本无技能词的岗）：如实保留为空 + 披露，或移出数据集——待定；
2. activity 层拆细词组（模型评测 / 推理性能优化 等）：属于扩词表决策，与「数据零改动」冲突，暂缓；
