# 6819 条 JD 里的 AI Infra 技能版图

> 数据集：国内 12 家 AI 公司官方招聘渠道的在招岗位说明（JD），共 6819 条，采集于 2026-11-19，全部为 JD 全文。按招聘渠道分为**社招 3407 条**与**校招 3412 条**。来源公司：字节跳动、阿里巴巴、腾讯、美团、蚂蚁集团、快手、小红书、阶跃星辰、MiniMax、智谱 AI、月之暗面 Kimi、DeepSeek。

想整理一份 AI Infra 方向的学习材料索引时，遇到一个问题：该学什么、按什么顺序学，现有的说法基本靠个人印象。「推理引擎是核心」「K8s 必须会」这类判断对不对、有多普遍，需要一个市场口径的坐标系。岗位描述（JD）是现成的坐标来源：每一家公司为想要的能力标了价，写明了要求。

这次把 12 家公司的官方招聘入口全部打通：抓取到 34369 个在招岗位（字节社招接口受 1 万条展示上限约束），按「AI Infra / Agent / 大模型训练 / 大模型推理」筛出 6978 条，转换入库 6819 条（6 条状态非「招聘中」跳过、137 条纯应用算法岗位剔除、16 条关键词误中的非 AI 岗人工剔除）。社招与校招分开统计、分开成文，两类岗位的市场画像差异很大，混在一起会互相污染。抓取与转换细节见 [README](README.md)。

产出是数据集本身加六样衍生物：分类报告（`analysis/classification.md`）、技能树三份（`analysis/skill-tree.md` 全库与 `skill-tree-society.md` / `skill-tree-campus.md` 分渠道），以及四个可交互页面：社招的 [skill-map-society.html](skill-map-society.html)（技能地图：三视角总览、谱系树、学习路线、技术栈×类别热力）与 [jobs-society.html](jobs-society.html)（岗位版图：类别分布、城市矩阵、逐条明细检索），校招的 [skill-map-campus.html](skill-map-campus.html) 与 [jobs-campus.html](jobs-campus.html)（同结构，基于校招子集）。分类体系的唯一定义源是 [`data/skill_catalog.json`](data/skill_catalog.json)：六个岗位类别、十六个岗位细分（全部用行业通用岗位名）、109 个技能词的 taxonomy（每个词标注 kind / type / scope / work_type）、六条岗位线的学习路线，全部脚本只引用这份定义、不做内部定义。这篇文章讲清楚三件事：数据怎么来的、社招与校招各自呈现出的样子、从 JD 到学习路线怎么推导。

## 一、数据怎么来的

12 家公司的招聘系统各不相同：飞书 ATS（字节、智谱、MiniMax）、Moka（阶跃、Kimi、DeepSeek）、各家自建站（阿里、腾讯、美团、快手、小红书、蚂蚁）。抓取工具先抓到 34369 个岗位，再用关键词筛出与 AI Infra / Agent / 大模型训练 / 大模型推理相关的 6978 条，最后转换成统一 schema 入库。

采集原则：取页面正常展示给访客的内容，职责照抄原文，抓不到就记录原因放弃。华为与百度的招聘系统没有公开接口，缺席。

四点采集口径先说清楚，后文的所有数字都受它们影响：

其一，筛选口径是宽的。「大模型训练 / 大模型推理相关」会把算法岗大量收进来：title 含算法 / Research / RLHF / 预训练等词的归入大模型算法细分，全批算法类 2152 条（占 32%）。Agent 岗按 title 关键词归研发类，其中「Agent 算法工程师」类 title 与工程岗 title 混在同一个细分里（见折扣清单）。

其二，入库时对 title 明写「算法」且落算法类的岗位做相关性判定：title 含模型词（大模型 / LLM / 多模态 / 语音等）的保留；title 含应用信号（推荐、搜索、调度、增长、风控等）直接剔除，不看正文；两类信号皆无的看正文是否有训练 / 推理证据。共剔除 137 条纯应用算法岗。另设一道人工复核：美团本地生活线的调度主管、腾讯游戏 QA、阿里渠道销售等 16 条岗位因「调度」「评测」等关键词误中筛选条件，逐条核对后人工剔除（名单在 `data/manual_exclusions.json`）。title 不含「算法」的岗位（如测试开发、运维）不受算法闸门影响。

其三，JD 正文普遍偏短。标题加职责全文的中位数只有 419 字（90 分位 808 字，按职位名与拆分后职责字段拼接统计），社招中位数 354 字。这直接影响技能词的命中率，第二节展开。技能词全集 109 个（taxonomy 定义，数据中出现 101 个），分三个视角组织：主题词（大模型、Agent、多模态这类市场在谈什么）、技术栈词（CUDA、vLLM、模型量化这类可学习的具名对象）、工作内容词（评测、性能优化这类岗位动作）。匹配按全文进行（英文词加边界、量化一词排除轻量化/向量化/可量化与量化策略/量化投资等非模型量化语境），仍有 73 条（1.1%）一条技能词都没命中。三个视角的词各算各的榜，不混排比较，这是本文所有技能数字的口径。

岗位细分的命名也交代一句：十六个方向全部用行业通用岗位名（大模型算法、Agent 应用、推荐算法、推理系统、训练系统、算子与高性能计算、Infra 工程、平台与调度、网络系统、存储系统、通用研发、产品与运营、测试/评测、SRE、GPU/IDC 运维、模型运维），由 title 关键词规则按优先级派生，规则表就在 skill_catalog.json 里，无命中的落「通用研发」。

## 二、社招版图（3407 条）

**类别分布**：研发 2224 条（65%），算法 796 条（23%），测试 247 条（7%），SRE 69 条，产品与运营 38 条，运维 33 条。测试、SRE、产品与运营、运维四个小类别合计约 11%，其中 SRE 与运维几乎只从社招招人（全库 SRE 91 条、运维 54 条，社招占 69 与 33）。

**公司分布**：字节跳动 1377 条，占社招的 40%。阿里巴巴 774、腾讯 333、蚂蚁集团 198、快手 138、美团 135、小红书 131 为第二梯队。模型公司体量小但岗位纯度高：阶跃星辰 101、智谱 89、MiniMax 77、Kimi 39、DeepSeek 15。「市场整体」的任何叙事都要记得四成样本来自字节一家的社招口径。

**城市分布**：北京 1940、杭州 1183、上海 1047、深圳 485，四城按提及次数合计约 94%（城市总提及 4929 次）。杭州的构成值得单独看：1183 条里阿里 606、字节 315、蚂蚁 170，阿里仍居半壁，字节快速跟进，杭州的 AI Infra 需求已经是「阿里加字节」的双引擎结构。新加坡 20 条，头部公司的出海岗位开始出现在国内社招渠道里。

**方向分布**：Agent 应用 876 居首，大模型算法 749 次之，通用研发 635 第三。技术方向里，测试/评测 247、Infra 工程 190、推理系统 182、平台与调度 130、训练系统 83、SRE 69；其余细分依次为算子与高性能计算 51、推荐算法 47、网络系统 40、产品与运营 38、存储系统 37、GPU/IDC 运维 21、模型运维 12。研发类内部，推理系统岗位是训练系统的两倍多（182 对 83），与推理部署规模化的行业阶段直接相关。

**技能谱系**按三个视角分开看，三榜口径不同，不互相比较。完整榜单见本地分析报告 `analysis/skill-tree-society.md`，页面 [skill-map-society.html](skill-map-society.html) 可交互核对。

主题覆盖率（市场在谈什么）：行业默认词「大模型/LLM」2281 条（67%），绝大多数 JD 默认提及，只说明「这是 AI 行业」，单独置顶不参与排名。其余主题词里，Agent框架 1924（56%）、模型训练 1285（38%）、模型推理 1212（36%）、多模态 1030（30%）构成第一梯队；强化学习 343（10%）、机器学习 322（9%）、芯片 235（7%）、预训练 214（6%）随后。主题词说明这个市场在做什么：过半岗位与 Agent 相关，训练与推理两个主题覆盖近四成岗位。

技术栈（要学什么，仅统计 technique 词，按学习单元类型分段，组间不比较）：方法类词的显式要求最多，Agent 侧 RAG 373、提示词工程 318，AI Infra 侧模型量化 299、RLHF 197、模型蒸馏 130、KV Cache 116、分布式训练 113、MoE 86；框架与引擎 vLLM 78、PyTorch 69、CUDA 53、SGLang 53；硬件互联 GPU 380（11%）、RDMA 70、RoCE 23；平台与工具 MCP 142、Kubernetes 116、Function Calling 40；语言 Python 140（4%）、Go 80、C++ 52。完整名单按学习单元类型（语言 / 框架 / 工具 / 硬件 / 数据系统 / 方法）与三个应用域（AI Infra / Agent Infra / 通用底座）分组，见分渠道技能树。

工作内容分布（岗位在干什么）：评测 995（29%）遥遥领先，微调 / SFT 567（17%）、性能优化 407（12%）、推理优化 218、模型部署 200 随后；角色词 SRE 79，指标词 SLA/SLO 106，能力保障词可观测性 165。岗位动作榜说明这个市场的日常工作构成：评测量大、调优重。

两层口径的解读方式：主题词说明「这个市场在做什么」；技术栈词说明「写出来的差异化要求是什么」。Python 占比只有 4% 不代表市场不需要 Python：社招 JD 正文普遍短（中位 354 字），这类通用技能常被默认隐含、不进差异化描述。可靠解读是：**写出来的词是岗位的差异化要求**。工作内容榜里微调 / SFT（567）与性能优化（407）被高频显式要求；方法类词整体由 Agent 侧的 RAG（373）与提示词工程（318）领先，AI Infra 侧方法词里模型量化（299）居首：训练与调优能力已经从加分项变成常规项。

## 三、校招版图（3412 条）

**结构特征先讲清楚**：校招批来自 11 家公司，字节跳动 1537 条占 45%。阿里巴巴 501、腾讯 386、蚂蚁集团 276、美团 201、快手 176、小红书 158 为其后。模型公司校招体量很小（MiniMax 66、阶跃星辰 51、Kimi 46、智谱 14），DeepSeek 的 15 条全部是社招。与社招相比，校招覆盖的公司更少、字节集中度更高（45% 对 40%），校招「市场」实际上更接近「几家大公司的校招口径之和」。

**类别分布**：研发 1728 条（51%），算法 1356 条（40%），测试 239 条（7%），产品与运营 46 条，SRE 22 条，运维 21 条。算法岗占 40%，高于社招的 23%，校招给算法应届生的名额相对更多。反方向更值得注意：SRE 与运维的校招合计只有 43 条（1.3%），而社招这两类合计 102 条。运维与稳定性岗位几乎完全不走校招渠道，想进这些方向，实习转正或社招是现实路径。

**城市分布**：北京 2063、上海 1309、杭州 1111、深圳 576，四城占比约 97%（城市总提及 5239 次），比社招（94%）更集中。北京的绝对量（2063）超过社招（1940），大公司的校招岗位更多落在总部所在地。杭州的校招构成里阿里 435、字节 328、蚂蚁 246，双引擎结构与社招一致。新加坡 11 条。

**方向分布**：大模型算法 1252 居首，Agent 应用 888 次之，通用研发 371 第三。技术方向里，测试/评测 239、Infra 工程 145、推理系统 140、推荐算法 104、训练系统 88；其余细分依次为产品与运营 46、网络系统 30、平台与调度 28、算子与高性能计算 27、SRE 22、GPU/IDC 运维 11、存储系统 11、模型运维 10。推理系统对训练系统约 1.6 倍（140 对 88），「推理重于训练」的排列与社招一致。

**技能谱系**同社招分三个视角，完整榜单见本地分析报告 `analysis/skill-tree-campus.md`，页面 [skill-map-campus.html](skill-map-campus.html) 可交互核对。

主题覆盖率：行业默认词「大模型/LLM」2794 条（82%）置顶单列，比社招的 67% 高出 15 个百分点，校招 JD 的写法更「主题化」。其余主题词：Agent框架 1932（57%）、模型训练 1707（50%）、多模态 1573（46%）、模型推理 1537（45%）构成第一梯队，四类主题的密度全面高于社招（对应 56% / 38% / 30% / 36%）；强化学习 622（18%）的密度接近社招（10%）的两倍。

技术栈（同社招按类型分段，组间不比较）：方法类词的显式要求最多，模型量化 333（9.8%）、RAG 313、提示词工程 197、RLHF 194、模型蒸馏 180、分布式训练 147（4.3%）、MoE 109、KV Cache 95；框架与引擎 CUDA 73、PyTorch 62、vLLM 48、Megatron 42、SGLang 37；硬件互联 GPU 288（8.4%）、RDMA 57；语言里 Python 只有 85 条（2.5%），C++ 40、Go 17。与社招相比，技术栈词的绝对密度普遍更低（JD 更短、更主题化），但训练类方法词（分布式训练 4.3% 对 3.3%、模型蒸馏 5.3% 对 3.8%）密度反而更高。

工作内容分布：评测 1011（30%）居首，微调 / SFT 636（18.6%）、性能优化 319（9%）、推理优化 310（9%）、模型部署 149（4.4%）、数据合成 198 随后；角色词 SRE 28、指标词 SLA/SLO 32、能力保障词可观测性 66，三者密度都远低于社招（79 / 106 / 165），稳定性与保障类工作几乎不进校招 JD。

与社招对比有两个差异值得说。其一，主题词密度全面更高：大模型/LLM 从 67% 升到 82%，多模态从 30% 升到 46%。校招 JD 更倾向于描述做的是什么方向，而不是列具体工具；Python 在校招只有 85 条（2.5%），这类通用技能被默认隐含，不写不代表不需要。其二，训练入口技能在校招写得更直白：强化学习的密度是社招的近两倍（18.2% 对 10.1%），微调 / SFT 18.6% 对 16.6%，分布式训练 4.3% 对 3.3%；模型量化两边相当（校招 9.8%、社招 8.8%）。训练与对齐是应届生进入这个市场的主要叙事，这个信号在校招 JD 里比社招更醒目。

校招渠道里实习岗 1763 条，占校招的 52%：应届进入这个市场的第一步，大多以实习开始。

## 四、按岗位的学习路线

路线的先后顺序是编辑判断：以技能间的依赖关系为主（底层语言先于框架，框架先于调优）、JD 频次为参考，个别低频技能按岗位常识排序（如平台与调度线的 Ray、Go 在 JD 里显式提及很少，但仍属该方向的基本盘），JD 原文本身没有顺序。六条线全部定义在 skill_catalog.json 的 roadmaps 里，页面上每条技能标注该技能在对应方向 JD 中的显式提及条数（方向内没有显式提及的技能，页面回退为整条线的计数），数字为全库口径。

**算法线**（算法类 2152 条，公共底座 Python → PyTorch）：

- 大模型算法方向（2001 条）：大模型/LLM → 多模态 → 模型量化 → RLHF → 推理优化
- 推荐算法方向（151 条）：大模型/LLM → 多模态 → 推理优化 → PyTorch → 模型量化

**研发线**（研发类 3952 条，公共底座 Python → Linux → Docker）：

- Agent 应用方向（1764 条）：Agent框架 → RAG → MCP → 多模态
- 推理系统方向（322 条）：模型量化 → KV Cache → 推理优化 → vLLM → SGLang → CUDA → Triton
- 训练系统方向（171 条）：PyTorch → 分布式训练 → RLHF → MoE → 模型量化
- 平台与调度方向（158 条）：Kubernetes → 可观测性 → Ray → Go → Docker
- 算子与高性能计算方向（78 条）：CUDA → Triton → CUTLASS → 性能优化 → GPU
- 网络系统方向（70 条）：RDMA → InfiniBand → RoCE → NCCL
- 存储系统方向（48 条）：NVMe → KV Cache → 性能优化 → GPU

研发类另有通用研发（1006 条）与 Infra 工程（335 条）两类未设独立路线：前者是无方向词的兜底细分，后者横跨基础设施各工种，两者合计占研发类的 34%，技能准备参考上方各方向按目标岗位取用。

**测试线**（测试类 486 条，底座 Python → Linux）：AI 测试 / 评测方向：CI/CD → 大模型/LLM → Agent框架 → 模型量化 → 性能优化。测试岗的标题已经以模型与 Agent 系统的评测为主：486 条里 400 条显式写了「评测」（82%）。

**SRE 线**（SRE 类 91 条，底座 Linux → Python）：平台稳定性方向：SLA/SLO → 可观测性 → GPU → 故障排查 → RDMA。SRE 岗的 AI 化程度高：四成 SRE 岗把 GPU 写进了技能要求（37/91）。

**运维线**（运维类 54 条，底座 Linux → Python）：

- GPU/IDC 运维方向（32 条）：大模型/LLM → GPU → Kubernetes → 模型部署 → SLA/SLO
- 模型运维方向（22 条）：大模型/LLM → Agent框架 → RAG → 模型部署 → GPU

**产品与运营线**（84 条，无技术底座）：大模型/LLM → Agent框架 → 多模态 → 模型量化 → 模型部署。这是六条线里唯一以非技术岗为主的线（84 条中仍含少量技术向岗位，如大模型安全对抗、数据策略专家）：产品与运营岗不写代码，但要能对齐模型能力边界、Agent 产品形态与量化部署的成本账，这条链按该方向 JD 的显式提及频次排出。

校招求职者的使用方式：算法线与研发线的入口技能（Python、PyTorch、分布式训练、模型量化）在校招 JD 里有直接频次，照路线学习即可；SRE 与运维两条线校招名额极少（合计 43 条），应届进入主要靠实习转正。校招渠道的实习岗 1763 条与算法线、研发线的前三个方向高度重合（大模型算法 680、Agent 应用 397、通用研发 197），可以作为切入口统计。

## 五、总评

这份数据把几个流传甚广的印象摆到了数字面前。研发类内部，推理系统岗位（322 条）接近训练系统（171 条）的两倍，「推理时代」在招聘口径上成立。工作内容榜里，评测以 2006 条居首，微调 / SFT（1203）、性能优化（726）、推理优化（528）、模型部署（349）随后：这个市场的日常工作由评测与调优构成，训练与部署动作都被显式写进要求。技术栈按类型分段看：方法类词的显式要求最多，RAG（686）、模型量化（632）、提示词工程（515）居前，RLHF（391）、模型蒸馏（310）、分布式训练（260）说明训练与对齐方法仍是常规要求；硬件类里 GPU（668）的显式密度远超同类的 RDMA（127）；主题覆盖率里 Agent 框架相关岗位过半（56.5%），训练（44%）与推理（40%）两个主题几乎平分秋色、训练略高。网络侧 RDMA（127 条）仍是一百多个岗位的显式要求，而 InfiniBand 修正匹配口径后只剩 26 条：写 IB/InfiniBand 的多是网络专岗，高速互联的普及度远没有 RDMA 高。测试类 486 条里 400 条显式写了评测，AI 测试已经是成建制的招聘方向。社招与校招的分册统计还补了两个常被忽略的事实：SRE 与运维几乎不招应届，入口在实习与社招；产品与运营作为唯一的非技术类别单独成类，它要求的技术词汇与工程岗高度重叠，差别在深度而不在广度。

引用这份数据时的折扣清单：

1. **筛选口径偏宽**。算法类 2152 条（32%）由 title 关键词派生：1691 条 title 明写「算法」，461 条由 研究 / Research / RLHF / 预训练 等词进入（这部分不经过应用算法闸门），其中约百条是工程 / 系统 title（如预训练数据工程师、推荐大模型后台开发工程师），算法岗与工程岗混合；Agent 应用 1764 条归研发类，同样约六成 title 是工程岗；
2. **字节占 43%**（2914/6819；社招 40%、校招 45%）。类别、方向、技能的分布都被字节的招聘口径主导，跨公司结论需按公司分层；
3. **方向由 title 关键词规则派生**。规则表在 skill_catalog.json，无命中的落「通用研发」（1006 条，占 15%）；title 关键词无法区分同一方向内的算法岗与工程岗；
4. **技能词是全文匹配**。词表 109 个（数据中出现 101 个），英文词加了边界，「量化」排除轻量化 / 向量化 / 可量化与量化策略 / 量化投资等非模型量化语境，仍有 73 条（1.1%）未命中任何技能词；responsibilities 字段里约 15% 的记录混入了原文的任职要求段（来源职责与要求本就合并在一段）；
5. **salary 与 level 字段全空**（来源不提供），薪资与职级维度不可分析；
6. **华为与百度缺席**，无法覆盖；
7. 数字随招聘进度每日变动，采集于 2026-11-19，引用前建议核对最新抓取。
