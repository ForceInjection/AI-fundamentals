# AI Infra 校招版图：3412 条校招 JD 的岗位与技能

> 数据集：国内 12 家 AI 公司官方招聘渠道的校招在招岗位说明（JD），共 3412 条，采集于 2026-11-19，全部为 JD 全文，来自 11 家公司（DeepSeek 校招为零，缺席本文）。全库 6819 条的总体版图见 [01-岗位技能版图.md](01-岗位技能版图.md)，本文只拆校招这一个面。

一个应届生想进 AI Infra，要回答三个问题：哪些方向对校招开门、这些方向要求什么技能、机会在哪家公司哪个城市。市面上关于「应届生能不能做 Infra」的说法基本靠个人印象，这份数据把答案摆在了 3412 条校招 JD 上：每一条都是一家公司真实挂在官网上的校招或实习岗位，写明了要什么人、要什么技能、在哪个城市。

产出的全量数据与方法见 [README](README.md)。与本文配套的还有两个可交互页面：[skill-map-campus.html](skill-map-campus.html)（校招技能地图：三视角总览、谱系树、学习路线、技术栈热力）与 [jobs-campus.html](jobs-campus.html)（校招岗位版图：类别分布、城市矩阵、逐条明细检索）——本文的每个数字都可以在页面里逐条核对。分类体系的定义与口径也见 [README](README.md)，这里只重复影响结论的三条：筛选口径偏宽，大模型训练 / 推理相关的算法岗也被收进来（算法类 1356 条，占校招 40%，即大模型算法与推荐算法两个细分）；title 明写「算法」且落算法类的岗位做了训练/推理相关性判定，纯应用算法岗已剔除——但算法类 1356 条里有 401 条是由 研究 / RLHF / 预训练 等词进入的，不经过这一闸门；技能词按全文匹配（词表 109 个，数据中出现 101 个，分主题 / 技术栈 / 工作内容三个视角），19 条校招记录（0.6%）未命中任何技能词。

## 一、哪些方向对校招开门

把每个细分方向的校招条数除以它的全库条数，得到「校招可及性」：一个方向挂出的所有 JD 里，有多大比例是对校招（含实习）放出的。它回答的问题是——应届生想进这个方向，校招直投这条路本身够不够宽。比例高，说明这个方向习惯从应届生里补人；比例低，说明它只从有经验的人里挑，硬投校招命中率很低。

按比例分三档：

**敞开**（校招占全库过半）：推荐算法 69%、大模型算法 63%、产品与运营 55%、训练系统 51%、Agent 应用 50%。大模型算法一个细分就有 1252 条校招 JD，是全库最大的校招方向；推荐算法校招占比最高（104/151），补员几乎完全靠校招。

**半开**（四到五成）：测试/评测 49%、模型运维 45%、推理系统 43%、Infra 工程 43%、网络系统 43%。推理系统有 140 条校招，说明推理方向并非只招有经验的人——量化、KV Cache 这些入口技能在校招 JD 里写得明确。

**门缝**（三成半以下）：通用研发 37%、算子与高性能计算 35%、GPU/IDC 运维 34%、SRE 24%、存储系统 23%、平台与调度 18%。平台与调度最极端：全库 158 条里校招只有 28 条，Kubernetes、调度策略这类方向基本只从有生产经验的人里挑，SRE 与存储同理。

两点补充。其一，比例低不等于绝对机会少：通用研发可及性只有 37%，但绝对量 371 条排校招第三——只是它作为无方向词的兜底细分，不适合当作一个明确的「方向」来规划。其二，算子与高性能计算比例不高（35%），但 27 条的绝对量仍是真实机会，CUDA/Triton 是敲门砖。

对应届生的含义很直接：目标定在大模型算法、Agent 应用、测试评测，校招直投这条路本身够宽；目标定在平台调度、存储、SRE，直接投校招命中率很低，实习转正是更现实的入口。

## 二、公司版图：11 家，字节一家占 45%

校招来自 11 家公司：字节跳动 1537 条（45%），阿里巴巴 501、腾讯 386、蚂蚁集团 276、美团 201、快手 176、小红书 158 为第二梯队。模型公司校招体量很小：MiniMax 66、阶跃星辰 51、月之暗面 Kimi 46、智谱 AI 14。DeepSeek 校招为零，它的 15 条岗位全部在社招渠道。

公司之间的类别结构差异比数量差异更有信息量。字节以 1537 条覆盖全部六个类别（研发 797、算法 539、测试 130、运维 18、SRE 15、产品与运营 38）；六类全开的还有一家——只有 66 条的 MiniMax（研发 49、算法 11、测试 1、运维 2、SRE 1、产品与运营 2），是唯一做到这一点的模型公司。阿里与腾讯的算法岗比例明显更高（阿里算法 223 接近研发 236，腾讯算法 192 反超研发 180），两家把校招算法名额给得很足。其余模型公司各有侧重：阶跃研发与算法对半（23/23），智谱 14 条里算法占 9。

技能要求上也能看出公司差异，而且方向相反。字节校招 JD 写得最「主题化」：大模型/LLM 1344（87%）、Agent框架 920（60%）、多模态 771（50%），具体工具词很少——Python 在字节的校招 JD 里只出现 17 次（1%），PyTorch 1%、Megatron 0%。模型公司恰好相反：智谱 14 条条条写了大模型/LLM，Python 密度 43%、Megatron 21%、PyTorch 21%；阶跃星辰 Python 密度 53%、Megatron 25%；月之暗面 46%。岗位越少、越聚焦的公司，把要求写得越具体。MiniMax 则在基础设施技能上点名最狠：GPU 密度 33%、Kubernetes 15%（字节分别是 6% 和 1%）。

## 三、城市：北京一座城占四成，四城占九成七

校招岗位的城市分布比社招更集中：北京 2063 次提及（一条 JD 涉多城市分别计入），占校招城市总提及（5239 次）的 39%；上海 1309、杭州 1111、深圳 576 随后，四城合计约 97%。广州（73）全部是研发与算法类；成都（69）以研发与算法为主，另有 8 条测试。

北京的绝对量（2063）超过社招（1940），大公司的校招名额更多落在总部所在地。杭州的校招构成是「阿里加字节」双引擎（阿里 435、字节 328、蚂蚁 246），与社招结构一致。类别层面，四个主要城市全部以研发为最大类别；算法岗占比在上海（39%）与北京（40%）相近，城市之间没有明显的方向分工。

## 四、校招 JD 的技能谱系：更主题化，入口技能写得更明白

校招的技能数字按三个视角分开统计，三榜口径不同、不互相比较。完整榜单见本地分析报告 `analysis/skill-tree-campus.md`，页面 [skill-map-campus.html](skill-map-campus.html) 可交互核对。

主题覆盖率：行业默认词「大模型/LLM」2794 条（82%）置顶单列，绝大多数校招 JD 默认提及，只说明「这是 AI 行业」。其余主题词：Agent框架 1932（57%）、模型训练 1707（50%）、多模态 1573（46%）、模型推理 1537（45%）构成第一梯队；强化学习 622（18%）、机器学习 455（13%）、预训练 411（12%）随后。校招 JD 更倾向于描述做的是什么方向，而不是列具体工具。

技术栈（仅统计 technique 词，按学习单元类型分段，组间不比较）：方法类词的显式要求最多，模型量化 333（9.8%）、RAG 313、提示词工程 197、RLHF 194、模型蒸馏 180、分布式训练 147（4.3%）、MoE 109、KV Cache 95；框架与引擎里 CUDA 73、PyTorch 62、vLLM 48、Megatron 42、SGLang 37；Agent 侧平台工具 MCP 72、Function Calling 14；硬件互联 GPU 288（8.4%）、RDMA 57；语言里 Python 只有 85 条（2.5%），C++ 40、Go 17——通用技能被默认隐含，不写不代表不需要。

工作内容分布：评测 1011（30%）居首，微调 / SFT 636（18.6%）、性能优化 319（9%）、推理优化 310（9%）、数据合成 198、模型部署 149（4.4%）随后；角色词 SRE 28、指标词 SLA/SLO 32、能力保障词可观测性 66，密度都很低——稳定性与保障类工作几乎不进校招 JD。

与社招对比有两个结构性差异。其一，主题词密度全面更高：大模型/LLM 从社招的 67% 升到 82%，多模态从 30% 升到 46%，模型训练从 38% 升到 50%。其二，训练入口技能在校招写得更直白。强化学习的密度是社招的近两倍（18.2% 对 10.1%），微调 / SFT 18.6% 对 16.6%，分布式训练 4.3% 对 3.3%。这批 JD 说明得很清楚：对应届生，进入这个市场的第一个技能动作是训练与对齐，而不是部署调优——模型量化在校招的密度也只有 9.8%（社招 8.8%），排位在几个训练类词之后。

类别内部的差异同样清楚。校招算法类（1356 条）的主题词以大模型/LLM（1193）、多模态（870）、模型训练（731）、模型推理（629）、Agent框架（549）、强化学习（329）为主，工作内容词里微调 / SFT（325）、评测（311）靠前——训练与对齐词汇占主导。校招研发类（1728 条）则是大模型/LLM（1337）、Agent框架（1214）、模型训练（852）、模型推理（834）、多模态（601），工作内容词里评测（481）、微调 / SFT（275）靠前，部署与调优词（性能优化 228、推理优化 204）随后。两个类别都以训练为第一叙事，研发类比算法类多了部署词。

## 五、实习：校招的另一半

校招渠道的 3412 条里，实习岗 1763 条，占 52%——校招「市场」的另一半其实是实习。这个比例意味着，讨论应届进入 AI Infra，只看正式校招 offer 会漏掉一半的入口。

实习岗的方向分布与校招整体一致但更集中：大模型算法 680、Agent 应用 397、通用研发 197、测试/评测 151、Infra 工程 71。大模型算法的实习占该方向校招的 54%——这个方向的一半以上校招名额以实习形式放出。结合第一节的可及性数据，应届进入 AI Infra 的典型路径是：校招或实习进入大模型算法 / Agent 应用 / 测试评测这类「校招友好」方向，积累一到两年后再转向平台调度、SRE 等社招主导的方向。

## 六、按方向的学习路线

路线的先后顺序是编辑判断：以技能间的依赖关系为主、JD 频次为参考，个别低频技能按岗位常识排序，JD 原文本身没有顺序。六条线全部定义在 skill_catalog.json 的 roadmaps 里，页面上的每条技能标注它在对应方向校招 JD 中的显式提及条数，下文的括号数字为该方向的校招条数。

**算法线**（算法类 1356 条，公共底座 Python → PyTorch）：

- 大模型算法方向（1252 条）：大模型/LLM → 多模态 → 模型量化 → RLHF → 推理优化
- 推荐算法方向（104 条）：大模型/LLM → 多模态 → 推理优化 → PyTorch → 模型量化

**研发线**（研发类 1728 条，公共底座 Python → Linux → Docker）：

- Agent 应用方向（888 条）：Agent框架 → RAG → MCP → 多模态
- 推理系统方向（140 条）：模型量化 → KV Cache → 推理优化 → vLLM → SGLang → CUDA → Triton
- 训练系统方向（88 条）：PyTorch → 分布式训练 → RLHF → MoE → 模型量化
- 平台与调度方向（28 条）：Kubernetes → 可观测性 → Ray → Go → Docker
- 算子与高性能计算方向（27 条）：CUDA → Triton → CUTLASS → 性能优化 → GPU
- 网络系统方向（30 条）：RDMA → InfiniBand → RoCE → NCCL
- 存储系统方向（11 条）：NVMe → KV Cache → 性能优化 → GPU

**测试线**（测试类 239 条，底座 Python → Linux）：AI 测试 / 评测方向：CI/CD → 大模型/LLM → Agent框架 → 模型量化 → 性能优化。

**SRE 线**（SRE 类 22 条，底座 Linux → Python）：平台稳定性方向：SLA/SLO → 可观测性 → GPU → 故障排查 → RDMA。

**运维线**（运维类 21 条，底座 Linux → Python）：GPU/IDC 运维（11 条）与模型运维（10 条）两条泳道，技能以大模型/LLM、GPU、Kubernetes、模型部署为主。

**产品与运营线**（46 条，无技术底座）：大模型/LLM → Agent框架 → 多模态 → 模型量化 → 模型部署。六条线里唯一以非技术岗为主的线（仍含少量技术向岗）：不写代码，但要能对齐模型能力边界与量化部署的成本账。

对应届生的使用方式：算法线与研发线的入口技能（Python、PyTorch、分布式训练、模型量化）在校招 JD 里有直接频次，照路线学习即可；SRE、运维、平台与调度三条线校招名额太少（合计 71 条），技能路线仍然成立，但进入时机建议放在实习转正或首次社招。

## 七、总评

这批校招数据回答了开头三问。哪些方向开门：大模型算法（1252 条）、Agent 应用（888 条）、测试/评测（239 条）是校招的三个主入口，校招可及性都在一半上下；平台与调度（18%）、存储（23%）、SRE（24%）基本对校招关闭。要求什么：校招 JD 写方向多于写工具，主题词里模型训练（50%）与模型推理（45%）双双覆盖近半校招岗；例外的是训练入口技能，写得很直白：工作内容榜里微调 / SFT（636 条）仅次于评测（1011 条），技术栈榜里模型量化（333 条）、RLHF（194 条）、模型蒸馏（180 条）、分布式训练（147 条）的显式提及都超过一百条。机会在哪：字节一家占 45%，北京一座城占城市提及的四成；模型公司校招体量小（四家合计 177 条），作为雇主选择的确定性有限。

引用这份数据时的折扣清单：

1. **字节占 45%**。校招的类别、方向、技能分布都被字节的招聘口径主导，跨公司结论需按公司分层；
2. **方向由 title 关键词规则派生**。规则表在 skill_catalog.json，无命中的落「通用研发」（371 条）；title 关键词无法区分同一细分内的算法岗与工程岗，Agent 应用里约六成 title 是工程岗；
3. **技能词是全文匹配**。词表 109 个（数据中出现 101 个），仍有 0.6% 的校招记录未命中任何技能词（全库 1.1%）；responsibilities 字段约 15% 的记录混有原文的任职要求段；
4. **校招口径含实习**。1763 条实习岗占 52%，实习岗位的竞争性质与正式校招不同，引用比例时注意分母；
5. **salary 与 level 字段全空**，薪资与职级维度不可分析；
6. **华为与百度缺席**，模型公司校招体量小（合计 177 条），「模型公司校招」的结论受小样本影响；
7. 数字随招聘进度每日变动，采集于 2026-11-19，引用前建议核对最新抓取。
