# 《FDE：AI落地实战指南》：把 AI 塞进业务现场的操作手册

我们那篇[《模型不稀缺了，稀缺的是把模型塞进业务的人》](forward-deployed-engineer.md)给的判断是：模型不稀缺了，稀缺的是能把模型塞进业务的人。文章沿着 80/95/99 规律、三道被 AI 拉低的成本门槛、本体层与三级复制杠杆，讲清了这个岗位是什么、为什么在 2026 年突然紧缺。

读完它，你知道该往哪个方向走了，但不知道第一步该踩在哪。樊中恺的《FDE：AI落地实战指南》接的就是这一问。

---

## 一、写这本书的人

樊中恺是百度主任架构师、文心应用技术负责人，主导了文心 App 从技术预研到工程落地的全过程，在百度内部带队打破算法、工程、应用和产品的边界。

这个背景决定了书的性质。中文材料里，FDE 这个题目下面已经有几份，彼此不重复：

| 材料                                   | 作者身份                           | 提供什么                                         |
| -------------------------------------- | ---------------------------------- | ------------------------------------------------ |
| 腾讯研究院《FDE模式行业观察与实践》    | 研究机构                           | 机制解释：为什么是现在、能不能规模化             |
| 范冰《前线部署工程师（FDE）》          | 研究整理（全文开源）               | 岗位定义、一次交付的完整旅程、案例汇编           |
| Jove Zhong《我在 AI 异世界重生为 FDE》 | 北美 AI Agent 公司 FDE 负责人      | 一线体感：时间分配、能力画像、对窗口期的判断     |
| **樊中恺《FDE：AI落地实战指南》**      | 百度主任架构师、文心应用技术负责人 | 系统方法论：七篇三十章，外加一套可直接用的工具包 |

前三份讲清楚了 FDE 为什么存在、长什么样、做起来是什么感觉。第四份落在操作层面：进场之后第一天干什么、怎么问出真需求、Demo 做到什么程度算够、上线之后靠什么活下来。它写的是中文语境里的项目，面对国内组织、真实的审批链和汇报周期，这部分前三份材料没有覆盖。

## 二、七篇三十章

全书七篇、三十章，另加结语与附录。

| 篇     | 章    | 章节构成                                                                                        |
| ------ | ----- | ----------------------------------------------------------------------------------------------- |
| 认知篇 | 1–4   | 装修毛坯房的人 / 它从哪里来：一套打法的二十年 / 九成五：一个行业的集体尴尬 / FDE 的一天与一年   |
| 能力篇 | 5–9   | 一专多能的 T 型人；与客户、业务方、技术方、组织四方沟通                                         |
| 方法篇 | 10–12 | 业务洞察：理解客户真正的问题 / 问题定义：把模糊需求变成可做的事 / Demo 驱动：用最小成本证明价值 |
| 技术篇 | 13–17 | 大模型基础认知、提示词工程、RAG、工具调用与智能体、成本效果与延迟的三角                         |
| 交付篇 | 18–21 | 为什么 Demo 不能直接上线 / 数据与知识治理 / 安全性、可靠性与合规 / 影响与推进                   |
| 案例篇 | 22–27 | 保险、企业知识助手、金融、制造与能源、教育、政务医疗与专业服务                                  |
| 成长篇 | 28–30 | FDE 成长路线 / FDE 面试实战 / 就算你不当 FDE                                                    |

这个结构里，有两处安排是有意的。

**技术篇只有五章，而且全是"够用就好"的口径。** 第 13 章的标题就叫"大模型基础认知：够用最好的心智模型"。这本书没打算把读者培养成算法工程师，技术部分的目标是让 FDE 能判断"这个问题 AI 能不能解、该走哪条路径"。这与 FDE 这个角色的实际构成一致：写代码只占三分之一时间。

**认知篇放在最前面，第四章就谈"一天与一年"。** 多数技术书从环境搭建写起，这本先让读者看清这份工作的时间去哪了、节奏什么样，再谈方法。对一个正在考虑转型的人来说，这个顺序比反过来有用得多。

## 三、三处先看的内容

### 五种死法

企业 AI 项目常见的死法，书里归成五类：

- **演示型**：项目从立项起就是为了三个月后那场汇报，掌声热烈之后，系统再也没有被打开过
- **数据型**：模型选得好，但喂给系统的文档有三个版本、两套口径
- **流程型**：AI 跑通了，但业务流程一个字没改，员工需要额外打开一个网页，两周后所有人回到老办法
- **信任型**：系统整体不错，但有一次给出了一个自信的错误答案，恰好被有影响力的人看见，信任瞬间崩塌
- **归属型**：系统上线，供应商撤场，内部没有明确负责人，慢慢失效，无人惋惜

作者自己的批注是：五种里只有一种带点技术色彩，其余四种全部属于组织问题。

这个判断和我们那篇长文里"80 到 99 这一段，多数问题不在模型能力"是同一件事，只是这里换成了五个可以拿来对照自查的具体形态。对照着数一数自己手上那个项目中了哪几条，比读一遍方法论更直接。

### 换一种问法

访谈客户时问"您有什么痛点"，从来问不出真痛点。书里建议换个问法：

- "能带我走一遍您昨天实际处理的那一单吗？"
- "上一次出岔子是什么时候？当时发生了什么？"
- "您平时有没有自己整理什么表格，帮自己记这些？"

书里有一段访谈案例：一位理赔员随口说了句"出了事是我的名字挂在上面呢"，直接改变了项目方向。原本客户要的是全自动审核，最后做成了 AI 预读加人工决策。

这句抱怨之所以关键，是因为它点出了一个访谈问不出来的约束：审核员本人承担着签名的责任，全自动审核恰好把这个责任主体抹掉了。这类约束写不进需求文档，只能到工作现场去看。

### 工作化石

同一个部分里还有一条信号：在几乎每一个企业客户那里，都散落着员工自己做的小工具——一张维护了五年的 Excel 表、一个用宏拼出来的自动填表器。

判断的依据是：**没有人会为了一个不痛苦的问题，牺牲自己的下班时间去做一张表。**

这些"工作化石"是需求最诚实的信号，因为它们绕过了所有访谈技巧，直接显示了哪些环节真的让人难受。FDE 的价值，就是把这些私底下的自救工具，变成企业级的生产力系统。

## 四、第 22 章：一个项目按周复盘

案例篇六章里，第 22 章"全程复盘：远洋保险理赔智能助手"是按周推进的：

第 0 周进场时的局面 → 第 1–2 周潜伏期 → 第 3 周一场改变方向的会 → 第 4–6 周第一个 Demo → 第 7–16 周生产化的十周 → 第 17–30 周采用期 → 第 31 周以后沉淀与撤出

后面接三节："数字复盘""三次差点翻车的时刻""这个项目做错的五件事"。

这种写法在中文技术书里不多见。多数案例文止于成果，而这三节把可复制性最高的部分留了下来：哪里差点翻车、哪些决策事后看是错的。

## 五、附录与读法

附录是七件可以直接用的工具：FDE 能力自测表、客户访谈模板、AI 项目需求分析模板、Demo 设计模板、FDE 面试题库（60 题）、企业 AI 落地检查清单、术语表（75 词）。

按书的定位，给两条读法建议。

**如果你在考虑转岗**，先读第 4 章"FDE 的一天与一年"和第 28 章"FDE 成长路线"（含三种起点、90 天计划、四个台阶、薪酬行情、四种代价，以及"AI 会不会取代 FDE"），再回头补能力篇。判断要不要走这条路，比琢磨怎么走更要紧。

**如果你手上正有 AI 项目**，从五种死法和第 22 章那份全程复盘入手，对照自己的项目做一次体检，再按需查方法篇和交付篇。

这本书与我们那篇长文的分工是清楚的：长文给认知地图，把 FDE 放进 AI 落地的产业结构里去解释；这本书给操作手册，处理的是"明天进场该带什么、第一个问题问什么、什么程度算做完"。
